# Ray 分布式计算框架架构

Ray 是一个开源的分布式计算框架，专为扩展 Python 应用程序而设计，特别适用于机器学习和 AI 领域。Ray 的架构分为两个主要层次：**应用层（Application Layer）**和**系统层（System Layer）**。

## 一、应用层（Application Layer）

应用层是用户直接交互的接口，包括三个核心组件：

### 1. Driver（驱动节点）
- **作用**：用户编写的 Python 脚本，负责启动和管理 Ray 集群中的任务
- **功能**：
  - 定义远程函数（Remote Functions）和 Actor
  - 提交任务到 Ray 运行时
  - 协调整个分布式应用的执行流程

### 2. Workers（工作节点）
- **作用**：无状态的进程，负责执行任务（远程函数）
- **特点**：
  - 每个 worker 可以并发处理多个任务
  - 支持并行执行，提高吞吐量
  - 任务完成后，worker 可以被重新分配执行其他任务

### 3. Actors（执行器）
- **作用**：有状态的实体，维护跨多个方法调用的本地状态
- **应用场景**：
  - 强化学习中的环境管理
  - 需要维护状态的长期运行服务
  - 模型推理服务的状态管理

## 二、系统层（System Layer）

系统层是 Ray 的核心基础设施，提供分布式执行所需的底层服务：

### 1. Global Control Store (GCS) - 全局控制存储
- **作用**：分片的键值存储，维护集群中任务、Actor 和对象的元数据
- **存储内容**：
  - 任务规范（Task Specifications）
  - 序列化的代码
  - 计算图（Computation Graphs）
  - 对象位置信息
  - 调度事件
- **重要性**：确保集群的一致性和容错性

### 2. Scheduler（调度器）
- **架构**：采用分层调度架构，包括本地调度器和全局调度器
- **工作流程**：
  1. **本地调度**：每个节点有一个本地调度器，优先尝试将任务分配给本地资源
  2. **全局调度**：如果本地资源不足，任务会被转发到全局调度器
  3. **调度决策**：全局调度器考虑集群范围内的资源可用性和数据局部性
- **优势**：自底向上的方法提高了可扩展性和响应速度

### 3. Object Store（对象存储）
- **作用**：分布式共享内存系统，管理由任务和 Actor 产生和消费的不可变对象
- **特点**：
  - **高效数据共享**：通过共享内存减少序列化开销
  - **分布式架构**：每个节点都有本地对象存储，这些存储相互连接形成集群范围的对象存储
  - **零拷贝**：同一节点上的进程可以直接访问共享内存中的对象
- **在 NeMo Curator 中的应用**：
  - 数据在管道阶段之间通过 Ray Object Store 流动
  - 减少数据移动，提高吞吐量
  - 支持流式处理，降低 I/O 开销

## 三、Ray 架构的关键特性

### 1. 统一框架
- 提供任务执行、状态管理和进程间通信的统一框架
- 支持从单机到大规模集群的无缝扩展

### 2. 容错性
- GCS 维护元数据，支持任务重试和故障恢复
- 自动处理节点故障和任务失败

### 3. 资源管理
- 动态资源分配和调度
- 支持 CPU、GPU 等异构资源管理
- 支持部分 GPU 分配（多个模型共享一个 GPU）

### 4. 数据局部性优化
- 调度器考虑数据位置，优先在数据所在节点执行任务
- Object Store 减少跨网络的数据传输

## 四、Ray 在 NeMo Curator 中的应用

NeMo Curator 基于 Ray 构建分布式数据处理管道，主要利用以下 Ray 核心能力：

### 1. 分布式 Actor 管理
- 在集群中创建和管理 Ray Actors
- 支持每个阶段的不同运行时环境（通过 Cosmos-Xenna）

### 2. Ray Object Store 和数据引用
- 使用 Ray 的对象存储和数据引用减少数据移动
- 提高管道阶段间的数据传输效率
- 支持流式执行模式

### 3. 自动扩缩容
- 监控每个阶段的吞吐量
- 动态调整 worker 分配
- 优化管道性能，平衡各阶段的资源使用

## 五、Ray 与其他分布式框架的对比

| 特性 | Ray | Dask | Spark |
|------|-----|------|-------|
| **编程模型** | Actor + Task | DataFrame | DataFrame/RDD |
| **状态管理** | 原生支持 Actors | 有限支持 | 需要额外设计 |
| **GPU 支持** | 原生支持 | 需要额外配置 | 有限支持 |
| **动态调度** | 是 | 是 | 否 |
| **Python 原生** | 是 | 是 | 否（主要 Scala） |
| **流式处理** | 是 | 是 | 是 |

## 七、总结

Ray 的分布式架构通过分层设计实现了：
- **可扩展性**：从单机到大规模集群无缝扩展
- **灵活性**：支持有状态和无状态计算模式
- **效率**：通过 Object Store 和智能调度减少数据移动
- **容错性**：GCS 和调度器提供故障恢复能力

这使得 Ray 成为构建大规模分布式 AI 数据处理系统（如 NeMo Curator）的理想基础框架。
