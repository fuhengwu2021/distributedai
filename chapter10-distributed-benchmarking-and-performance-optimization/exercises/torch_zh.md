## 参考答案与解析

1. B - 预热轮次用于消除 JIT 编译开销与硬件缓存冷启动噪音
2. B - TTFT 严格涵盖从输入分词、上下文 Prefill 矩阵乘法到生成首个 Token 的全过程
3. B - 代表取得了理想线性加速比（8 倍）的 85%，即实际实现了 6.8 倍线性加速
4. C - 在交互打字机模式下，TTFT 首字延迟直接决定了用户对系统是否即时响应的第一体感
5. B - `nccl:all_reduce` 与 `nccl:all_gather` 为 PyTorch 底层调用的 NCCL 集合通信算子
6. B - 阿姆达尔定律指出串行计算比例决定了无限并行时的理论加速极限
7. B - 探寻并发拐点，找到计算单元达到算力利用率饱和且排队时间未恶化的最佳工作点
8. B - 借助 CUDA 流同步屏障隔离异步指令队列，才能精确度量 GPU 纯通信事件
9. B - 两者均刻画在生成阶段产出连续 Token 之间的步进物理间隔耗时
10. B - 分布式环境若未正确实现全局 Loss 均值归约或未对齐 Batch 统计量，会导致显著的算法精度裂化
11. B - P95/P99 刻画了恶劣极端条件下的长尾尾部延迟，是服务等级 SLA 的硬性红线
12. C - 真实扩展效率即为 $N$ 卡总吞吐与单卡基线吞吐乘以 $N$ 理论值的比值：$\text{throughput}_N / (\text{throughput}_1 \times N)$
13. B - 展示各 GPU 之间是走高带宽 NVLink 还是受限的跨 NUMA PCIe 链路
14. B - 科学消除网络偶然拥塞与动态功耗墙调节带来的测量漂移，保证数据置信度

__简答题解析要点：__

15. **多卡扩展通信开销上升机制**：随着卡数与机器节点增加，一方面通信拓扑从高带宽节点内 NVLink（数百 GB/s）扩散到跨节点的物理以太网或 InfiniBand（通常仅数十 GB/s），跨机带宽受限；另一方面，AllReduce 的环路步数或树状深度增加，同步等待的长尾步调不一致（Straggler 效应）概率成倍放大。

16. **长尾延迟 10 倍分化成因**：典型的长尾（Tail Latency）问题表明 90% 以上的标准请求能高速响应，但部分请求遭遇了系统级阻塞。常见诱因包括：周期性内存垃圾回收（GC STW）、大请求 Prefill 抢占导致的自回归解码停顿（缺少 Chunked Prefill）、动态显存分配导致的物理内存碎片整理，或后端个别 GPU 发生过热降频。

17. **不改模型削减通信开销的方案**：

   - **梯度累积（Gradient Accumulation）**：通过在本地连续执行多个 Micro-batch 的前向与反向，将每步必做的 AllReduce 频率缩减为每 $K$ 步一次，有效稀释网络通信的固定延迟损耗。  
   - **通信与计算重叠（Overlap & Bucketing）**：合理调整参数分桶大小（Bucket Size），使得靠后层的反向梯度在执行 AllReduce 通信时，与靠前层的反向传播计算并发异步执行，将通信时间完全隐藏在计算耗时阴影之下。  
   - **通信压缩/量化（FP8/INT8 AllReduce）**：在发送梯度时进行低比特有损压缩，降低物理网络总线上的数据搬运体量。

18. **量化模型跨引擎精度差异根源**：即使模型权重参数完全同构，各引擎底层调用的 CUDA Kernel 算子实现不同（如 Marlin、AWQ 或 ExLlama 的反量化乘法算子）。在反量化重构、中间激活浮点截断、Softmax 累加归约顺序上存在细微浮点数值差异（IEEE 754 浮点数加法不满足结合律），累加到数十层网络后会导致概率分布产生轻微抖动。

19. **训练样本吞吐 vs 推理 Token 吞吐的本质差异**：

   - **训练 Samples/sec**：度量的是单位时间内完成前向、反向计算及权重更新的完整数据样本条数，由于训练期序列长度固定（或经过严格 Packing 对齐），样本数直接对应恒定的浮点计算次数（FLOPs）。  
   - **推理 Tokens/sec**：度量的是在线生成每秒吐出的离散 Token 总数。由于推理中不同请求的 Prompt 长度与生成结束时机完全动态异步，首字阶段（Memory-bandwidth/Compute bound）与解码阶段（Memory-bandwidth bound）的计算特性迥异，因此仅看 Token 吞吐必须结合输入输出长度比、批次并发度与 TTFT 进行综合评估。
